## Recommendation

Use this balanced production preset for long Thai legal RAG answers:

```json
{
  "temperature": 0,
  "top_p": 1,
  "repetition_penalty": 1.05,
  "max_tokens": 3072,
  "min_tokens": 0,
  "frequency_penalty": 0,
  "presence_penalty": 0,
  "chat_template_kwargs": {"enable_thinking": false}
}
```

The direct 4,096-cap repetition profile, the 3,072-cap recommended profile, and the Open WebUI custom preset produced the same answer SHA-256. The model stopped naturally at 2,675 tokens, so lowering the cap to 3,072 preserved the complete output while preventing the forced 5,120-token degeneration.

Do not use `min_tokens=4096`: it forced output to the 5,120-token cap, switched heavily into English, repeated source URLs, and returned `finish_reason=length`. Low-temperature sampling did not improve citation or substantive quality over deterministic decoding.

Parameter tuning improved output control, not legal truth. Even the recommended profile scored only 3.0/5 because it invented sample sizes and historical due dates and overstated some 30-day duties. Keep exact-section retrieval, a claim-to-source validator, completeness checks beyond `finish_reason`, and human legal review.

## Open WebUI deployment

The preset is installed as `OpenThai Legal Audit 12K (Balanced)` with model id `openthai-legal-audit-12k-balanced`. The Open WebUI route returned a byte-identical answer to the direct vLLM recommended profile, confirming that `repetition_penalty` and the other defaults were forwarded. Open WebUI must refresh `/api/models` after importing a new preset before the first chat request.
